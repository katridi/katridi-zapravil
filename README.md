# Катриди заправил

Репозиторий подкаста **«Катриди заправил»**.

В этом подкасте мои рассказы звучат голосами разных людей.

Здесь хранятся сайт подкаста, метаданные выпусков и RSS-лента.

## Архитектура

```text
GitHub
│
├── сайт
├── метаданные выпусков
└── RSS
     ↓
GitHub Pages
     ↓
сайт + feed.xml

Cloudflare R2
     ↓
MP3
```

RSS используется для публикации подкаста в:

- Яндекс Музыке
- Spotify
- Apple Podcasts
- YouTube / YouTube Music

## Выпуски

Каждый выпуск хранится в отдельном YAML-файле.

Пример:

```yaml
title: "Щенок"
season: 1
episode: 1

author: "Алексей Катриди"
reader: "Сергей Глебкин"

guid: "kz-s01e01"
date: "2026-09-20T09:00:00+03:00"

audio:
  url: "https://audio.example.com/s01/s01e01-shchenok.mp3"
  type: "audio/mpeg"

description: >
  Рассказ Алексея Катриди.
  Читает Сергей Глебкин.
```

После публикации `guid` выпуска нельзя менять.

## Аудио

Архивный мастер:

```text
WAV
mono
48 kHz
24-bit
```

Дистрибуционный файл:

```text
MP3
mono
48 kHz
CBR 192 kbps
```

MP3 не хранятся в GitHub.

Они загружаются в Cloudflare R2 и доступны по отдельному публичному URL.

## Обложка

Основная обложка:

```text
3000 × 3000 px
JPG или PNG
без прозрачности
```

Название должно оставаться читаемым в маленьком размере.

## Публикация нового выпуска

1. Подготовить финальный MP3.
2. Загрузить его в Cloudflare R2.
3. Добавить YAML-файл в `episodes/`.
4. Проверить название, описание, дату, URL аудио и `guid`.
5. Сделать commit и push в `main`.
6. Проверить обновлённый сайт и `feed.xml`.

После обновления RSS новый выпуск должен автоматически поступить на подключённые платформы.

## Важные правила

- не менять `guid` опубликованного выпуска;
- не удалять опубликованный MP3 без необходимости;
- не менять URL старого аудиофайла без проверки RSS;
- не хранить в репозитории пароли, API-токены и другие секреты.

При необходимости секреты хранятся в GitHub Secrets.

## RSS

Production RSS должен иметь постоянный публичный URL.

Например:

```text
https://katridizapravil.com/feed.xml
```

При будущем переезде на другой хостинг старый RSS должен отдавать постоянный `301 redirect` на новый feed.
