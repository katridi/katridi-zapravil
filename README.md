# Катриди заправил

Репозиторий подкаста **«Катриди заправил»**.

В этом подкасте мои рассказы звучат голосами разных людей.

Здесь хранятся сайт подкаста, метаданные сезонов и эпизодов и, в дальнейшем, RSS-лента.

## Архитектура

```text
GitHub
│
├── сайт
├── метаданные сезонов и эпизодов
└── RSS
     ↓
GitHub Pages
     ↓
сайт + feed.xml

Cloudflare R2
     ↓
MP3
```

RSS используется для публикации подкаста в:

- Яндекс Музыке
- Spotify
- Apple Podcasts
- YouTube / YouTube Music

## Структура репозитория

```text
katridi-zapravil/
│
├── seasons/
│   └── season-01/
│       ├── episode-01/
│       │   └── episode.yml
│       ├── episode-02/
│       │   └── episode.yml
│       └── ...
│
├── assets/
│   └── cover-placeholder.svg
│
├── scripts/
│   └── ...
│
├── index.html
├── style.css
├── README.md
├── AGENTS.md
└── .gitignore
```

Основная структура проекта строится по номеру сезона и эпизода, а не по названию рассказа.

Название рассказа хранится внутри `episode.yml`.

## Выпуски

Первый выпуск:

```text
seasons/
└── season-01/
    └── episode-01/
        └── episode.yml
```

Пример `episode.yml`:

```yaml
title: "Щенок"

season: 1
episode: 1

author: "Алексей Катриди"
reader: "Сергей Глебкин"

guid: "kz-s01e01"

date: "2026-09-20T09:00:00+03:00"

audio:
  url: "https://audio.example.com/s01/e01.mp3"
  type: "audio/mpeg"

description: >
  Первый рассказ мини-сезона «Воспоминания».
  Читает Сергей Глебкин.
```

После публикации `guid` выпуска нельзя менять.

Название рассказа можно изменить без изменения директории, URL или GUID.

## URL эпизодов

Предпочтительный формат URL:

```text
/s01/e01/
/s01/e02/
/s02/e01/
```

URL не должен зависеть от названия рассказа.

Это позволяет менять название эпизода, не ломая внешние ссылки.

## Аудио

Архивный мастер:

```text
WAV
mono
48 kHz
24-bit
```

Дистрибуционный файл:

```text
MP3
mono
48 kHz
CBR 192 kbps
```

MP3 не хранятся в GitHub.

Они загружаются в Cloudflare R2.

Предпочтительная структура:

```text
s01/
├── e01.mp3
├── e02.mp3
└── e03.mp3

s02/
├── e01.mp3
└── ...
```

Пример URL:

```text
https://audio.example.com/s01/e01.mp3
```

## Обложка

Основная обложка:

```text
3000 × 3000 px
JPG или PNG
без прозрачности
```

До получения финальной обложки используется placeholder.

Название должно оставаться читаемым в маленьком размере.

## Публикация нового выпуска

1. Подготовить финальный MP3.
2. Загрузить его в Cloudflare R2.
3. Создать директорию нового эпизода:

```text
seasons/season-01/episode-02/
```

4. Добавить в неё `episode.yml`.
5. Проверить:
   - `season`;
   - `episode`;
   - `guid`;
   - название;
   - описание;
   - дату;
   - URL аудио.
6. Сделать commit и push в `main`.
7. Проверить сайт и `feed.xml`.

После обновления RSS новый выпуск должен автоматически поступить на подключённые платформы.

## Важные правила

- не менять `guid` опубликованного эпизода;
- не переименовывать директории опубликованных сезонов и эпизодов без необходимости;
- не удалять опубликованный MP3;
- не менять URL старого аудиофайла без проверки RSS;
- не привязывать постоянные URL к названию рассказа;
- не хранить в репозитории пароли, API-токены или другие секреты.

При необходимости секреты хранятся в GitHub Secrets.

## RSS

Production RSS должен иметь постоянный публичный URL.

Например:

```text
https://katridizapravil.com/feed.xml
```

При будущем переезде на другой podcast-hosting старый RSS должен отдавать постоянный HTTP `301` redirect на новый feed.

## Сайт

На сайте размещаются:

- описание проекта;
- список сезонов;
- список эпизодов каждого сезона;
- страницы отдельных эпизодов;
- ссылки на Яндекс Музыку;
- Spotify;
- Apple Podcasts;
- YouTube / YouTube Music;
- дополнительные ссылки проекта.
